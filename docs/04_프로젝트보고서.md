## 1. 요약

자동화공장 통합 모니터링 시스템의 관제 화면 8종과 백엔드 2종(C++ 수집기 / C# 게이트웨이)
개발이 완료되었다. 남은 일정은 CCTV 중계 서버(NVR 교체 일정에 종속), 관제실 대형 모니터
표출 시험, 운전원 교육, 알람 합리화 1차다.

이번 과제는 **기능 추가가 아니라 설계 기준을 바꾸는 일**이었다.

현재 관제실에는 설비사가 각자 납품한 감시 화면이 5개 따로 떠 있고,
1차 통합 화면은 상태마다 색을 다 넣어서 알록달록하다. 알람은 하루 700~900건 뜬다.
운전원이 다 확인할 수 없으니 대부분 무시한다.

2026-05-14 CT-02 건조로 과열 때 알람이 40분간 떠 있었는데 아무도 못 봤다.
운전원이 다른 화면을 보고 있었고, 알람은 그 화면에 안 뜨는 구조였다.

## 2. 무엇을 바꿨나

### ① 색을 줄였다 (ISA-101)

평상시 화면에는 색이 거의 없다. 정상 공정값은 전부 저채도 회색이다.
색은 경고(앰버) · 알람(레드) · 조치필요(블루) 세 가지에만 쓴다.
브랜드 색(시안)은 네비게이션 전용으로 못 박아, 공정 데이터에는 쓰지 않는다.

결과적으로 **화면에서 색이 보이면 그 자체가 신호**가 된다.
1차 화면에서는 색이 늘 보였기 때문에 아무 신호도 아니었다.

### ② 알람 배너를 전 화면에 고정했다 (ISA-18.2)

어느 화면을 보고 있어도 최상단에 최우선 미확인 알람과 건수가 뜬다.
05-14 사고의 직접 원인이 화면 전환이었으므로, 이건 타협하지 않았다.

### ③ 알람 자체를 줄였다

하루 700~900건은 ISA-18.2 권고치(300건)의 2~3배다. 세 가지로 잡았다.

| 장치 | 내용 | 효과(추정) |
|---|---|---|
| 중복 억제 | 같은 태그·유형 알람이 활성이면 재생성 안 함 | -35% |
| 히스테리시스 | 한계값에서 deadband 만큼 복귀해야 해소 | -28% |
| 상태기반 억제 | 설비 정지 구간 알람 차단 (조치 불가) | -12% |

세 개를 합치면 하루 약 250~300건 수준이 된다. 여기에 빈발 알람 상위 10개의
한계값을 재설정하는 합리화 작업(11월)을 더하면 목표치에 들어온다.

미확인 상태로 해소된 알람은 목록에서 지우지 않고 `UnackCleared` 로 남긴다.
조용히 사라지면 무슨 일이 있었는지 아무도 모른다.

### ④ 화면 5개를 1개로 합쳤다

배합(LS 터치패널) · 코팅(미쓰비시 GOT) · CCTV(NVR 클라이언트) · 전력(엑셀) ·
가스검지(독립 판넬) → 웹 브라우저 하나.

## 4. 기술 선택과 근거

### 수집기를 C++ 로 쓴 이유

1초 주기로 8대 PLC, 1,284 태그를 폴링한다. 스캔이 밀리면 트렌드에 구멍이 생기고,
그 구멍이 사고 조사 때 문제가 된다. GC 일시정지를 신경 쓰지 않아도 되는 쪽을 골랐다.
상주 메모리 20MB 안쪽이라 현장 산업용 PC 에 올리기도 부담이 없다.

### 게이트웨이를 C# 로 쓴 이유

하는 일이 REST / SignalR / JSON / 시계열 관리다. 여기서 C++ 을 쓸 이유가 없다.
ASP.NET Core 에 다 들어 있어서 **NuGet 패키지를 하나도 쓰지 않았다** — 제어망
패키지 반입 심의를 통째로 피했다.

### 프레임워크·차트 라이브러리를 안 쓴 이유

같은 이유다. 관제 PC 는 폐쇄망이고 CDN 을 못 쓴다. 필요한 차트 5종(라인·막대·도넛·
게이지·스파크라인)을 400줄로 직접 그렸다.

## 5. 개발 중 잡은 결함

| 일자 | 증상 | 원인 | 조치 |
|---|---|---|---|
| 08-06 | XGT 태그 값이 뒤집혀 나옴 | 엔디언. Modbus=빅, XGT=리틀 | 프로토콜별 디코딩 분리 |
| 08-14 | PLC 1대 정지 시 전체 스캔 정지 | 블로킹 `connect()` 가 timeout 을 무시. OS 기본 20초까지 대기 | 논블로킹 + `select()` 로 교체 |
| 08-27 | 값이 경계에서 떨릴 때 같은 알람이 분당 수십 건 | 한계값 복귀 즉시 해소 판정 | 히스테리시스(deadband) 도입 |
| 09-19 | 미믹 화면이 1초마다 깜빡임 | SVG 전체 재그리기 | 값 노드만 부분 갱신 |
| 09-23 | MSVC 빌드 실패 (`std::min` 오류) | `windows.h` 의 min 매크로 | `NOMINMAX` 정의 |

**08-14 건**이 가장 위험했다. 증상은 "가끔 트렌드가 끊긴다" 정도로 보였는데,
실제로는 죽은 PLC 한 대 때문에 나머지 7대 감시가 20초씩 멈추고 있었다.
현장에 올렸으면 사고 때 데이터가 통째로 비었을 것이다.
