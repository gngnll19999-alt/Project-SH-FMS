| 항목 | 내용 |
|---|---|
| 문서번호 | SH-FMS-WI-2026-001 |
| 프로젝트 | 프로젝트SH (개인 프로젝트) |
| 작성 | 남성흠 |
| 과제명 | 자동화공장 통합 모니터링 시스템 구축 |
| 기간 | 2026-07-10 ~ 2026-11-15 (4개월) |
| 근거 | 사전조사 보고서 SH-PRE-2026-001 (벤치마킹 100건) |

> 개인 프로젝트다. 실제 공장이 발주한 과제가 아니라, 국내외 패키지와 국제표준을 조사해
> "이런 공장이 있다면 시스템을 어떻게 설계할 것인가"를 끝까지 밀어붙여 본 기록이다.
> 등장하는 공장·라인·품목·수치는 설계를 구체화하기 위해 세운 전제이며, 화면과 코드는 실제로 동작한다.

## 1. 과제 배경

현재 관제실에는 설비사가 각자 납품한 감시 화면이 5개 따로 떠 있다.
배합은 LS 터치패널, 코팅은 미쓰비시 GOT, CCTV는 NVR 전용 클라이언트, 전력은 엑셀.
운전원이 이상을 파악하려면 화면을 옮겨 다녀야 한다.

더 큰 문제는 **1차 관제 화면의 설계 자체**다.

- 상태마다 색을 다 넣어서 화면이 알록달록한데, 정작 이상이 발생해도 눈에 안 띈다.
- 알람이 하루 700~900건 뜬다. 운전원이 다 확인할 수 없어서 대부분 무시한다.
- 그 결과 2026-05-14 CT-02 건조로 과열 때 알람이 40분간 떠 있었는데 아무도 못 봤다.

이번 과제의 목적은 화면을 늘리는 게 아니라 **운전원이 이상을 실제로 발견하게 만드는 것**이다.
그래서 ISA-101(고성능 HMI)과 ISA-18.2(알람 관리)를 설계 기준으로 못 박았다.

## 2. 기능 범위

사전조사 100건 중 FMS 반영분(63~85, 96~100)을 8개 화면 + 백엔드 2개로 묶었다.

| # | 화면 | 파일 | ISA-101 계층 | 우선순위 |
|---|---|---|---|---|
| F-01 | 공장 전체 감시 | `app/overview.html` | Level 1 | 1 |
| F-02 | 라인 공정 미믹 | `app/line.html` | Level 2 | 1 |
| F-03 | 화학 배치 공정 | `app/chemical.html` | Level 2 | 2 |
| F-04 | 에너지 · 유틸리티 | `app/energy.html` | Level 2 | 3 |
| F-05 | CCTV 통합관제 | `app/cctv.html` | Level 3 | 1 |
| F-06 | 안전 관제 | `app/safety.html` | Level 3 | 2 |
| F-07 | 알람 관리 | `app/alarm.html` | Level 4 | 1 |
| F-08 | 트렌드 · 히스토리안 | `app/trend.html` | Level 4 | 2 |
| B-01 | C++ 태그 수집기 | `src/collector` | Level 1 | 1 |
| B-02 | C# 게이트웨이 | `src/SHFms.Server` | Level 2 | 1 |

## 3. 작업 지시 항목

### WI-01 설계 기준 확정 (07-10 ~ 07-24)

- [x] ISA-101 색 사용 규칙 문서화 — 평상시 무채색, 색은 이상에만

> 화면에서 색이 보이면 그 자체가 "봐야 할 것"이라는 신호가 되어야 한다.

## 4. 비기능 요구사항

| 구분 | 기준 |
|---|---|
| 스캔 주기 | 1초 (오버런 시 로그 필수) |
| 표출 지연 | 태그 변화 → 화면 반영 2초 이내 |
| 태그 수 | 1,284 (확장 여유 2,000) |
| 동시접속 | 관제 PC 6대 + 사무 20명 |
| 가용성 | 24시간 무중단. 게이트웨이 재기동 중 수집분은 큐잉 후 전송 |
| 해상도 | 관제실 4K(3840×2160), 사무 1920×1080 |
| 보안 | 제어망. 수집기는 API 키, 상위 연계는 읽기전용 API |
| 권한 | 등급 3(전권) / 2(ACK·셸빙) / 1(조회) |
| 감사 | PTZ 조작, ACK, 셸빙 이력 기록 |
