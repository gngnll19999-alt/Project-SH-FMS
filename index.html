FEMS / 중대재해처벌법 대응

HMI 설계 원칙

1차 관제실 화면은 상태마다 색을 다 넣어서 알록달록했습니다. 그런데 정작 이상이 발생해도 눈에 안 띄었습니다. 이번에는 ISA-101 원칙을 지키기로 하고 색 예산을 엄격하게 잡았습니다.

색 사용 규칙

  • 평상시 저채도 회색. 정상 운전 중에는 화면에 색이 거의 없습니다
  • 노랑 경고 — 규격 접근, 설정값 편차
  • 빨강 알람 — 상한상한/하한하한 초과, 트립
  • 파랑 조작자 조치 필요
  • 시안(브랜드색) 네비게이션 전용. 공정 데이터에는 쓰지 않습니다

화면 계층

  • Level 1 공장 전체 개요 — 핵심 지표 한눈에
  • Level 2 단일 유닛 + 일상 운전
  • Level 3 개별 설비 상세 · 진단 · 영상
  • Level 4 트렌드 · 알람 상세 · 분석
  • 알람 배너 어느 화면에 있든 최상단에 고정 — 다른 화면을 보다가 알람을 놓치면 안 됩니다

시스템 구성

ISA-95 계층에서 SH-FMS는 Level 2에 해당합니다. 상위 MES/ERP와는 읽기 전용 API로만 붙습니다.

Level 4
SH-ERP에너지 사용량 수신 (제조경비 배부 기초자료)
Level 3

데이터 경로

  • 수집 C++ 수집기가 PLC 를 1초 주기로 폴링
  • 정규화 엔지니어링 단위 변환 + 데드밴드 적용
  • 전송 게이트웨이로 배치 전송 (변화분만)
  • 저장 히스토리안에 시계열 적재
  • 배포 SignalR 로 브라우저에 실시간 푸시

설계 제약

  • 읽기 전용 본 시스템은 감시만 합니다. 설비 제어는 SCADA/PLC 권한
  • 히스토리안 경유 상위 시스템은 SCADA 서버가 아니라 히스토리안 읽기전용 API로만 접근
  • 망 분리 제어망과 사무망 사이에 단방향 게이트웨이
  • 외부 의존 없음 화면은 폐쇄망에서 CDN 없이 동작

C++ 수집기 · C# 게이트웨이

수집기를 C++로 쓴 이유는 단순합니다. 1초 주기로 8개 PLC · 1,284 태그를 폴링하는데 GC 일시정지로 스캔이 밀리면 곤란하기 때문입니다. 게이트웨이는 REST/SignalR/DB 연동이 주 업무라 C# (ASP.NET Core) 가 생산성이 훨씬 좋습니다.

C++ 수집기 — src/collector

// 폴링 루프 (main.cpp)
while (running) {
  auto t0 = steady_clock::now();

  for (auto& dev : devices) {
    auto raw = dev->read_block();      // 프로토콜별 구현
    store.apply(dev->id(), raw);        // 단위환산 + 데드밴드
  }

  uploader.flush(store.take_changed());  // 변화분만 전송
  sleep_until(t0 + scan_period);         // 주기 고정
}
  • 프로토콜 드라이버: Modbus TCP / LS XGT / Mitsubishi MC
  • 데드밴드로 불필요한 전송 제거 (네트워크 부하 ↓)
  • 스캔 주기 고정 — 지터를 로그로 감시
  • PLC 단절 시 지수 백오프 재접속

C# 게이트웨이 — src/SHFms.Server

// 태그 수신 → 알람 평가 → 브라우저 푸시
app.MapPost("/api/v1/tags/batch", async (
    TagBatch batch, TagStore store,
    AlarmEngine alarms, IHubContext<TagHub> hub) =>
{
    store.Apply(batch);
    var fired = alarms.Evaluate(batch.Values);

    await hub.Clients.All.SendAsync("tags", batch.Values);
    if (fired.Count > 0)
        await hub.Clients.All.SendAsync("alarms", fired);

    return Results.Ok(new { received = batch.Values.Count });
});
  • ASP.NET Core Minimal API + SignalR 실시간 푸시
  • ISA-18.2 알람 엔진 (우선순위 · 데드밴드 · 셸빙 · 상태기반 억제)
  • 히스토리안 적재 및 조회 API
  • ONVIF/RTSP → WebRTC 중계 세션 관리
